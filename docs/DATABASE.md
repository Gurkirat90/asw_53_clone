# Database schema

The backend stores everything in one SQLite file (default `backend/data/route53_clone.db`, set by
`DATABASE_URL`). The schema is defined by SQLAlchemy models in `backend/app/models/` and created
**only** by Alembic migrations (`backend/alembic/versions/`). The running app never calls
`create_all`; at startup it refuses to serve a database that is missing or not at the latest
migration (`Database not migrated: run make migrate`).

Current revision: `0001` (`0001_initial_schema.py`).

## Entity relationships

```text
users 1 ──── * sessions          (sessions.user_id        → users.id,        ON DELETE CASCADE)
users 1 ──── * hosted_zones      (hosted_zones.user_id    → users.id,        ON DELETE CASCADE)
hosted_zones 1 ──── * dns_records (dns_records.hosted_zone_id → hosted_zones.id, ON DELETE CASCADE)
dns_records 1 ──── * record_values (record_values.record_id → dns_records.id,  ON DELETE CASCADE)
```

Deleting a user removes their sessions, zones, records, and values. Deleting a zone removes its
records (user and system) and their values. Cascades are enforced by SQLite itself
(`PRAGMA foreign_keys=ON` is executed on every new connection), and the ORM relationships use
`cascade="all, delete-orphan", passive_deletes=True` so they defer to the database.

## Conventions

| Topic | Rule |
|---|---|
| Primary keys | `TEXT` UUID v4 strings generated by the backend; never accepted from clients. |
| Timestamps | `TEXT` ISO 8601 UTC with microseconds and an explicit offset, e.g. `2026-10-09T12:34:56.123456+00:00` (`UTCDateTime` type). Naive datetimes are rejected on write; reads return timezone-aware UTC datetimes. The fixed width makes text comparison equal time comparison. |
| Booleans | SQLite `BOOLEAN` (0/1). |
| JSON | `value_json` is compact JSON stored as `TEXT` (`JSONText` type). |
| Constraint names | Deterministic via a naming convention (`pk_`, `fk_`, `uq_`, `ck_`, `ix_` + table + columns), which keeps Alembic batch migrations reliable on SQLite. |
| Connections | `PRAGMA foreign_keys=ON` always; `PRAGMA journal_mode=WAL` for file databases. |

## Tables

### `users`

| Column | Type | Constraints |
|---|---|---|
| `id` | VARCHAR(36) | PK |
| `email` | VARCHAR(254) | NOT NULL, UNIQUE (`uq_users_email`), CHECK `email = lower(email)` |
| `display_name` | VARCHAR(200) | NOT NULL |
| `password_hash` | TEXT | NOT NULL; Argon2id hash (`$argon2id$...`), never plaintext |
| `is_active` | BOOLEAN | NOT NULL, default 1 |
| `created_at` | TEXT (UTC) | NOT NULL |

There is no sign-up. `python -m app.cli seed-demo-user` (`make seed`) creates the demo user from
`DEMO_USER_*` settings if it is missing and never overwrites an existing password unless
`--reset-password` is passed.

### `sessions`

| Column | Type | Constraints |
|---|---|---|
| `id` | VARCHAR(36) | PK |
| `user_id` | VARCHAR(36) | NOT NULL, FK → `users.id` ON DELETE CASCADE |
| `token_hash` | VARCHAR(64) | NOT NULL, UNIQUE; SHA-256 hex of the cookie token |
| `created_at` | TEXT (UTC) | NOT NULL |
| `expires_at` | TEXT (UTC) | NOT NULL; checked on every authenticated request |
| `last_seen_at` | TEXT (UTC) | NOT NULL; refreshed at most every 5 minutes |
| `revoked_at` | TEXT (UTC) | NULL until logout |

Indexes: `ix_sessions_user_id (user_id)`, `ix_sessions_expires_at (expires_at)`, plus the unique
index on `token_hash`. The raw token exists only in the `route53_session` cookie. Sessions that
expired more than a day ago are deleted opportunistically on login.

### `hosted_zones`

| Column | Type | Constraints |
|---|---|---|
| `id` | VARCHAR(36) | PK; internal, never exposed by the API |
| `zone_id` | VARCHAR(32) | NOT NULL, UNIQUE; public ID, `Z` + 20 uppercase alphanumerics |
| `user_id` | VARCHAR(36) | NOT NULL, FK → `users.id` ON DELETE CASCADE |
| `name` | VARCHAR(253) | NOT NULL; lowercase, no trailing dot. **Not unique.** |
| `zone_type` | VARCHAR(16) | NOT NULL, CHECK `zone_type IN ('PUBLIC','PRIVATE')`; immutable |
| `comment` | TEXT | NULL, CHECK `length(comment) <= 1000`; the only editable field |
| `created_at` | TEXT (UTC) | NOT NULL |
| `updated_at` | TEXT (UTC) | NOT NULL; set on every update |

Indexes: `ix_hosted_zones_user_id_name (user_id, name)` for search,
`ix_hosted_zones_user_id_created_at (user_id, created_at)` for list ordering.

### `dns_records`

A record *set*: one name + type within a zone, with one or more ordered values.

| Column | Type | Constraints |
|---|---|---|
| `id` | VARCHAR(36) | PK |
| `hosted_zone_id` | VARCHAR(36) | NOT NULL, FK → `hosted_zones.id` ON DELETE CASCADE |
| `name` | VARCHAR(253) | NOT NULL; canonical FQDN inside the zone (lowercase, no trailing dot) |
| `record_type` | VARCHAR(8) | NOT NULL, CHECK IN (`A`,`AAAA`,`CNAME`,`TXT`,`MX`,`NS`,`PTR`,`SRV`,`CAA`,`SOA`) |
| `routing_policy` | VARCHAR(16) | NOT NULL, default `'SIMPLE'`, CHECK IN (`SIMPLE`) |
| `ttl_seconds` | INTEGER | NULL (required by the service for user records); CHECK `0..2147483647` |
| `comment` | TEXT | NULL, CHECK `length(comment) <= 1000` |
| `is_system` | BOOLEAN | NOT NULL, default 0; only the backend sets it (apex NS/SOA) |
| `created_at` | TEXT (UTC) | NOT NULL |
| `updated_at` | TEXT (UTC) | NOT NULL |

Unique: `uq_dns_records_hosted_zone_id_name_record_type (hosted_zone_id, name, record_type)`; the
service layer checks the same rule first so it can return `409 RECORD_CONFLICT`.
Indexes: `ix_dns_records_hosted_zone_id_name`, `ix_dns_records_hosted_zone_id_record_type`.
`SOA` is accepted by the database only so the system SOA record can exist; users cannot create it.

### `record_values`

| Column | Type | Constraints |
|---|---|---|
| `id` | VARCHAR(36) | PK |
| `record_id` | VARCHAR(36) | NOT NULL, FK → `dns_records.id` ON DELETE CASCADE |
| `position` | INTEGER | NOT NULL, 0-based, CHECK `position >= 0` |
| `value_json` | TEXT (JSON) | NOT NULL; typed payload, shape depends on the parent `record_type` |
| `display_value` | TEXT | NOT NULL; computed by the backend formatter on every write |

Unique: `uq_record_values_record_id_position (record_id, position)`. The ORM loads values ordered
by `position`, so value order is deterministic. Updating a record replaces all of its values in
one transaction.

#### `value_json` shapes

| Type | `value_json` | `display_value` example |
|---|---|---|
| A | `{"value": "192.0.2.10"}` | `192.0.2.10` |
| AAAA | `{"value": "2001:db8::10"}` | `2001:db8::10` |
| CNAME | `{"value": "app.example.net"}` | `app.example.net` |
| TXT | `{"value": "v=spf1 include:example.net -all"}` | `"v=spf1 include:example.net -all"` |
| MX | `{"priority": 10, "exchange": "mail.example.net"}` | `10 mail.example.net` |
| NS | `{"value": "ns1.example.net"}` | `ns1.example.net` |
| PTR | `{"value": "host.example.net"}` | `host.example.net` |
| SRV | `{"priority": 10, "weight": 5, "port": 443, "target": "service.example.net"}` | `10 5 443 service.example.net` |
| CAA | `{"flags": 0, "tag": "issue", "value": "letsencrypt.org"}` | `0 issue "letsencrypt.org"` |
| SOA (system only) | `{"mname": "ns-1234.awsdns-05.invalid", "rname": "awsdns-hostmaster.invalid", "serial": 1, "refresh": 7200, "retry": 900, "expire": 1209600, "minimum": 86400}` | `ns-1234.awsdns-05.invalid awsdns-hostmaster.invalid 1 7200 900 1209600 86400` |

Validation, normalization, and the single `display_value` formatter live in
`backend/app/services/dns_validation.py` (rules: [API.md](API.md#validation-rules)). TXT and CAA
values are displayed in double quotes with `\` and `"` backslash-escaped.

**System records.** Creating a zone inserts, in the same transaction, an apex NS record
(TTL 172800, four distinct `ns-<1..2047>.awsdns-<00..63>.invalid` hosts) and an apex SOA record
(TTL 900, `mname` = the first name server, `rname` = `awsdns-hostmaster.invalid`, serial 1,
refresh 7200, retry 900, expire 1209600, minimum 86400). Both have `is_system = 1` and cannot be
changed or deleted through the API. The `.invalid` TLD guarantees they never resolve, so they
cannot be mistaken for real delegation data.

## Invariants (PRD §14.8)

- SQLite foreign keys are enabled on every connection.
- Timestamps are UTC ISO 8601 text.
- Mutations commit only after validation succeeds; compound writes (zone + system records,
  record + values) are single transactions.
- Zone deletion cascades through records and record values.
- Record-value ordering is deterministic (`position`).
- IDs are generated by the backend, never accepted from create requests.
- Ownership comes from the authenticated session and parent relationships, never from a
  client-supplied `user_id`.
- Migrations are applied before serving traffic (`make migrate`); the app checks this at startup.
- Seeding is idempotent.

## Design choices

- **`record_count` is computed, not stored.** A zone's record count is a `COUNT(*)` over
  `dns_records` (system records included), so it can never drift from the real data.
- **`display_value` is computed on write.** One backend formatter derives it from `value_json`
  whenever values are written. Clients never send it. It gives search (`q`) and table display a
  single, consistent text form without re-implementing formatting in SQL or in the frontend, and
  because it is always rewritten together with `value_json` in the same transaction, it cannot
  become inconsistent.
- **Duplicate zone names are allowed.** Route 53 lets separate hosted zones share a domain name
  (each has its own ID), so `(user_id, name)` is indexed but not unique (PRD D-004).
- **Values in child rows, not a JSON array on the record.** Ordered rows make per-value
  validation errors (`values.1.priority`), uniqueness of position, and value search simple.
- **Extra CHECK constraints** (TTL range, comment length, lowercase email, non-negative position)
  back up the service-layer validation so invalid data cannot be written even by mistake.

## Operations

- Apply migrations: `make migrate` (creates `backend/data/` if needed).
- Create the demo user: `make seed` (requires `DEMO_USER_PASSWORD` in `backend/.env`).
- Reset local data: stop the backend, delete `backend/data/route53_clone.db` (and its `-wal` /
  `-shm` files), then run `make migrate` and `make seed`.
- Back up: stop the backend (or use `sqlite3 backend/data/route53_clone.db ".backup backup.db"`).
- New schema change: edit the models, then from `backend/` run
  `.venv/bin/alembic revision --autogenerate -m "describe change"`, review the generated file,
  and commit it.
